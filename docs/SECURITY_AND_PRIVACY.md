# ASTRA — Security & Privacy Documentation
**Classification**: Prototype Security Assessment (Non-Production)  

---

## 1. Authentication

- **Mechanism**: Username/password authentication via `POST /api/auth/login`.
- **Password Storage**: Passwords are hashed using **scrypt** key derivation ($N=16384$, $r=8$, $p=1$, 32-byte derived key) with a unique cryptographically random 16-byte salt per password. Verification uses constant-time `hmac.compare_digest()` to prevent timing attacks.
- **Token Format**: HMAC-SHA256 signed JWT tokens with configurable expiry (default: 480 minutes / 8 hours).
- **Token Secret**: Auto-generated 48-byte `secrets.token_urlsafe()` key stored in `backend/data/secret.key`, or manually set via `ASTRA_SECRET_KEY` env var.
- **No Self-Registration**: There is no public `/register` endpoint. Only an authenticated `admin` can create accounts via `POST /api/admin/users`.

## 2. Authorization (RBAC)

All authorization is enforced **server-side** via the `require_roles()` FastAPI dependency in `security.py`. The frontend hides unauthorized routes for usability, but the backend independently rejects unauthorized API calls with HTTP 403.

| Role | Create Users | Manage Sensors | Manage Medical Rules | Run Simulations | View Sessions |
|---|---|---|---|---|---|
| `admin` | ✅ | ❌ (read-only) | ❌ (read-only) | ❌ | ✅ |
| `physical` | ❌ | ✅ | ❌ (read-only) | ❌ | ❌ |
| `medical` | ❌ | ❌ (read-only) | ✅ | ❌ | ❌ |
| `operator` | ❌ | ✅ (read-only) | ✅ (read-only) | ✅ | ✅ |
| `viewer` | ❌ | ❌ | ❌ | ❌ | ✅ (token-scoped) |

## 3. Viewer Token System

- Viewer tokens (`ViewerToken` model) are session-scoped, read-only bearer tokens issued by operators.
- Transmitted via `X-Viewer-Token` header or `?token=` query parameter (for WebSocket).
- Tokens are revocable by the operator and tied to a specific `sim_session.id`.
- Viewers cannot access sensor configurations, medical rules, admin functions, or any write operation.

## 4. Login Throttling

Failed login attempts are rate-limited per IP address to mitigate brute-force attacks. The throttle logic is in `security.py`.

## 5. Input Validation

All API request bodies are validated through **Pydantic v2** schemas (`schemas.py`, `schemas_lab.py`). Invalid payloads return HTTP 422 with structured validation error details.

## 6. Security Headers

The HTTP middleware injects on every response:
- `X-Content-Type-Options: nosniff` — Prevents MIME sniffing attacks.
- `Referrer-Policy: no-referrer` — Prevents referrer leakage.

## 7. CORS Configuration

- Configurable via `ASTRA_CORS_ORIGINS` (default: `http://localhost:5173,http://127.0.0.1:5173`).
- In production (single-port deployment via `scripts/start.ps1`), CORS is not needed since the frontend is served from the same origin.

## 8. API Key Management

- LLM API keys (`ASTRA_LLM_API_KEY`, `OPENROUTER_API_KEY`, `GROQ_API_KEY`, etc.) are read from environment variables only.
- Keys are never logged, never stored in the database, and never included in API responses.
- If no key is configured, ASTRA falls back to the deterministic local engine with zero network dependency.

## 9. Sensitive Data Handling

> [!IMPORTANT]
> ASTRA processes **zero real personal health information (PHI)**. All physiological data is generated by deterministic simulation models. No HIPAA, GDPR, or medical data privacy regulations apply to the simulated telemetry.

## 10. Secret Protection

- `.env` files containing real credentials are excluded via `.gitignore`.
- `.env.example` contains only placeholder values — no real API keys.
- The auto-generated JWT `secret.key` file is inside `backend/data/`, which is gitignored.

## 11. Known Security Limitations (Prototype)

| Item | Status | Notes |
|---|---|---|
| HTTPS / TLS Enforcement | **Not Implemented** | Development runs over plain HTTP. Production deployments should terminate TLS via a reverse proxy (nginx, Caddy). |
| Password Complexity Rules | **Not Implemented** | No minimum length or character class enforcement on the backend. |
| Refresh Token Rotation | **Not Implemented** | JWT tokens are single-use until expiry; no refresh token mechanism. |
| CSRF Protection | **Not Applicable** | API is token-authenticated (no cookies), so CSRF does not apply. |
| Demo Account Passwords | **Documented in README** | Demo accounts use predictable passwords for hackathon evaluation convenience. For any real deployment, set `ASTRA_DEMO_PASSWORD` to override all demo credentials. |

## 12. Dependency Security

All Python dependencies are pinned with minimum version bounds in `requirements.txt`. Frontend dependencies are locked via `package-lock.json`. No known critical CVEs affect the current dependency set (as of November 2026). Teams should enable GitHub Dependabot alerts for ongoing monitoring.
